# hypetype-mac — ТЗ на рефакторинг (`PLAN.md`)

Документ-компаньон к `FORMAT.md`. Описывает рефакторинг macOS-версии hypetype (Swift) в три изолированных этапа. `FORMAT.md` — контракт формата файла раскладки, общий с Windows-версией; этот документ — план приведения мак-кода к этому контракту и к чистой архитектуре.

**Главная цель проекта:** единый файл раскладки `config.ini` работает на Windows и macOS без конвертации (копируешь файл — раскладка переехала). Всё остальное подчинено этому.

---

## 0. Принципы работы

1. **Не портировать, а удалять.** Защитный код вокруг проблем, которых в сэндбоксе не бывает, не переносится — удаляется. Итоговый код должен быть короче текущего.
2. **Границы этапов — «зелёное» состояние.** Каждый этап заканчивается состоянием, которое собирается, запускается, проходит ручной чек-лист (§6) и закоммичено. Это страховка от прерывания (лимит сессии, ребут): возобновление всегда дешёвое.
3. **Коммит после каждого шага.** Внутри этапа — мелкие шаги с коммитами, чтобы было куда откатываться и откуда продолжить.
4. **Этапы строго последовательны.** Этап 2 не начинается, пока Этап 1 не «зелёный». Самый рискованный, трогающий данные кусок (формат) изолирован в Этап 2 и идёт по уже чистому коду.
5. **Поведение для пользователя на Этапе 1 не меняется.** Только внутренняя чистота. Это позволяет сравнить «было/стало».

## 1. Целевая архитектура

Единый источник правды + чистое разделение «данные / ввод / UI / персистентность». Каждый модуль — отдельный файл.

### Core (данные, чистая логика — покрывается тестами)
- **`KeyDefinitions.swift`** — **единственный** источник правды по таблице клавиш: 48 записей `{ w3cName, macKeyCode, displayLabel }` строго по `FORMAT.md` §5. Из него выводятся: дефолтная раскладка, ряды редактора, имена клавиш, автокомментарии. Заменяет пять текущих дубликатов (`getDefaultMappings`, `getKeyComment`, `KeyCodeMapper.keyName`, ряды в `KeyboardEditorViewModel`, справочный комментарий в `KeyCodes.swift`).
- **`LayoutFormat.swift`** — чистый парсер/сериализатор формата `config.ini` v2: разбор строк (§2.1), hex-кодек значений (§4), рендер автокомментариев (§6), round-trip чужих секций (§7). Никакого I/O, никакого UI — только `String ⇄ модель`. Полностью тестируемый.
- **`GlyphRenderer.swift`** — общий рендер «кодпоинт(ы) → человекочитаемый глиф» (`0020`→`␣`, `00A0`→`⍽`, `200B`→`ZWSP`, диакритика на носителе `◌`, пусто→`—`). Используется и автокомментариями `config.ini` (§6), и подписями клавиш в редакторе. Задел под будущий UI (Этап 4).
- **`Layout.swift`** — доменная модель раскладки в памяти: словарь `w3cName → (alt: [Scalar], altShift: [Scalar])` + сохранённые «чужие» секции/ключи для round-trip.

### Persistence
- **`LayoutStore.swift`** — файловый слой: чтение/запись `config.ini`, путь к файлу, миграция legacy-JSON (§8.2 FORMAT.md), бэкап перед миграцией. Использует `LayoutFormat` для (де)сериализации. Заменяет персистентную часть `MappingManager`.
- **`SettingsStore.swift`** — `isEnabled` и прочие приложенческие настройки в `UserDefaults` (бывший `SettingsManager`, без `useClipboardMethod`).

### Input (перехват и ввод)
- **`EventTapManager.swift`** — `CGEventTap`, детект правого ⌥ через `flagsChanged` (§5 — НЕ ТРОГАЕМ), маршрутизация в инсертер/диакритику. Чистится, логика не меняется.
- **`SymbolInserter.swift`** — прямой ввод Unicode-событиями + clipboard-путь для пробелов (с сохранением/восстановлением **всего** pasteboard).
- **`DiacriticController.swift`** + **`DiacriticIndicatorWindow.swift`** — режим ожидания диакритики и HUD-индикатор.

### App / UI
- **`hypetypeApp.swift`** — точка входа.
- **`AppDelegate.swift`** — menu bar, жизненный цикл, разрешения Accessibility, автозапуск.
- **`KeyboardEditorView.swift`** + **`KeyboardEditorViewModel.swift`** — редактор, проекция `KeyDefinitions` + `Layout`. Подписи клавиш — через `GlyphRenderer`.

## 2. Этап 1 — Чистка и компонентизация
**Формат конфига НЕ трогаем (остаётся текущий JSON). Поведение для пользователя идентично.**

### Шаги
1. **Удалить мёртвый/опасный код** (подтверждено grep'ом, ни одна из функций не вызывается):
   - `MappingManager.forceCreateTestFile()` — пишет не-JSON в боевой `config.json`, при вызове убил бы конфиг.
   - `EventTapManager.needsClipboard()` + поле `clipboardCache` — не используется (везде прямой ввод).
   - `EventTapManager.resetState()` — не вызывается (авто-сброс инлайнится в `handleEvent`).
   - `AppDelegate.createMenuBarIcon()` + `createSimpleTextIcon()` — не вызываются (`setupMenuBar` грузит иконку инлайн).
   - `SettingsManager.useClipboardMethod` — DEPRECATED, всегда `false`.
   - Сцена `Settings { SettingsView() }` + `struct SettingsView` — недостижима из меню (accessory-app), дублирует README, хардкодит «Версия 1.0».
   - Протухший комментарий в `KeyCodes.swift` (ссылка на несуществующий `testMappings`).
2. **Свести таблицу клавиш в `KeyDefinitions.swift`** — один источник, остальные пять мест переписать на него.
3. **Расклеить на модули** по §1 (без изменения поведения): вынести `SymbolInserter`, `DiacriticController`+`DiacriticIndicatorWindow`, `AppDelegate`, `SettingsStore` в отдельные файлы.
4. **Починить буфер обмена:** в clipboard-пути сохранять и восстанавливать **весь** pasteboard (`NSPasteboardItem` всех типов), а не только `.string`. Сейчас при вставке символа-пробела уничтожается картинка/RTF в буфере.
5. **Задержки и логирование:** где безопасно — ужать `usleep`/`asyncAfter` и сделать `isInserting` детерминированным (снимать флаг по факту, а не по таймеру 50 мс, где это возможно); где задержка load-bearing (гонка с системной обработкой синтетических `CGEvent`) — оставить и пометить комментарием «так надо». Десятки `print` — под единый `os.Logger` с флагом, в release молчит.

### Выход Этапа 1 (критерии «зелёного»)
- Собирается без warning'ов, иконка в menu bar, вкл/выкл «Виртуализации» работает.
- Все символы из дефолтной раскладки вводятся как раньше; диакритика работает; буфер обмена с картинкой переживает вставку пробела.
- Старый `config.json` читается и пишется как прежде.
- Пройден §6.

## 3. Этап 2 — Переход на кросс-платформенный формат
**Это и есть киллер-фича. Самый «трогающий данные» этап — идёт по уже чистому коду.**

### Шаги
1. **`LayoutFormat.swift`** — реализовать парсер/сериализатор `config.ini` v2 строго по `FORMAT.md`: правила строки (§2.1), hex-кодек с лимитом 32 кодпоинта и валидацией диапазона/суррогатов (§4), автокомментарии через `GlyphRenderer` (§6). Покрыть юнит-тестами на эталонном примере (§9 FORMAT.md) и на идемпотентность.
2. **Round-trip (§7)** — при загрузке сохранять неизвестные секции/ключи; при записи возвращать их байт-в-байт. Обязательный тест: `load → save → load` не теряет ни секции, ни ключа. Мак не трогает `[Windows]`.
3. **`LayoutStore.swift`** — переключить чтение/запись на `config.ini`. Путь — рядом с текущим в Application Support контейнера. Имя файла — `config.ini` (см. FORMAT.md §2).
4. **Миграция legacy-JSON (§8.2)** — при старте: если найден старый `config.json` и нет `config.ini` — мигрировать. Бэкап `config.json.old`. **Конвертация строк строго по Unicode scalars, не по графемам** (иначе эмодзи/диакритика → битые кодпоинты). `keyCode` (int) → W3C-имя по таблице §5.
5. **`KeyDefinitions` → W3C-имена** как канонические ключи; мак-keycode остаётся внутренней колонкой трансляции для `EventTapManager`.

### Выход Этапа 2
- Файл `config.ini`, идентичный по структуре виндовому, читается/пишется; round-trip-тест зелёный.
- Старый `config.json` мигрируется один раз, с бэкапом, без потери символов (включая эмодзи и диакритику).
- **Главная проверка:** файл, сохранённый на маке, открывается виндовой версией и наоборот — раскладка переносится.
- Пройден §6.

## 4. Этап 3 — Модуль типографа + ёфикатор

Переносим на мак функциональность, уже реализованную и специфицированную для Windows (см. `TYPOGRAPH.md` Windows-репозитория — он остаётся источником правил; здесь только специфика порта).

### Шаги
1. **`Typograph.swift`** — чистая функция `typograph(_ text: String) -> String`. Правила переносятся из `TYPOGRAPH.md`: кавычки (автомат состояний), тире, многоточие/пунктуация, чистка пробелов, неразрывные, числа/валюта. Регулярки — на `NSRegularExpression`/ICU. Требование идемпотентности (повторный прогон не портит текст) — красной строкой, каждый тест гоняется дважды.
2. **Ёфикатор** — мини-словарь однозначных словоформ как ресурс бандла (данные, не код), отдельной включаемой группой. Логика переносится из виндовой реализации.
3. **Хоткей** — повесить на существующий `EventTapManager` (аналог RAlt+Backspace на винде — выбрать мак-эквивалент аккорда). Механика: выделил → хоткей → выделение заменяется типографированным текстом.
4. **Вставка** — переиспользовать clipboard-round-trip из `SymbolInserter` (сохранить весь буфер → скопировать выделение → типографировать → вставить → восстановить буфер). Краевые случаи как в `TYPOGRAPH.md` (ничего не выделено → тултип, буфер восстановлен).

### Выход Этапа 3
- Паритет с Windows-версией по типографу на «золотом корпусе»; идемпотентность; буфер не теряется.
- Пройден §6 + типограф-кейсы.

## 5. Что НЕ трогаем

**Детект правого ⌥ через `CGEventTap` + `flagsChanged` (keyCode `0x3D`).** Это осознанный и правильный выбор, а не костыль: прямого способа «забрать правый ⌥ из системы» в userland-macOS нет; `hidutil`-ремап не умеет слой-модификатор и требует перезапуска скрипта после ребута; путь Karabiner — это system-extension-драйвер (тяжелее по следу, требует одобрения расширения, теряет мгновенное вкл/выкл). `CGEventTap` даёт «тыкнул — сразу работает, тыкнул — выключилось» без перезагрузки. Логика детекта переносится **как есть**, только переезжает в чистый модуль. Любой рефакторинг этого блока — отдельный разговор, не в этом проекте.

## 6. Чек-лист ручного тестирования (прогонять на границе каждого этапа)

1. **Правый ⌥ (самый средозависимый пункт — первым):** ввод символов с R⌥ и R⌥+Shift в TextEdit, Safari/Chrome, Figma, Adobe, Telegram. Проверить отсутствие конфликтов с системными и приложенческими хоткеями. Залипание флага после Alt+Tab / переключения окна.
2. **Диакритика:** R⌥+Shift+V → буква → склейка (ǧ), таймаут 5 с, HUD-индикатор появляется/исчезает, не крадёт фокус.
   - ⚠️ **Известная проблема (НЕ наш баг):** ударение над кириллицей (`а́` = буква + U+0301) визуально «не садится» на букву на macOS 26.5. Воспроизводится и на старой сборке, и в раскладке Бирмана → это изменение рендеринга combining-знаков в самой ОС, а не регрессия рефакторинга. Технически приложение отдаёт **корректный** Unicode (база + combining acute); у большинства русских гласных прекомпозированной формы в Unicode нет, поэтому `precomposedStringWithCanonicalMapping` правомерно оставляет 2 скаляра. **Чинить мутацией кодпоинтов нельзя** — это сломает корректную работу в других ОС/шрифтах. Склейка в один глиф — зона ответственности шрифта/текстового движка. Перепроверить на следующих апдейтах macOS.
3. **Пробелы и буфер:** вставка символа-пробела не уничтожает картинку/RTF, лежащую в буфере обмена.
4. **Последовательности/эмодзи:** многокодпоинтные значения (дивайдер `␣·␣`), эмодзи (😎) вводятся целиком.
5. **Редактор:** открыть, отредактировать клавишу, сохранить, проверить что изменение применилось вживую без перезапуска.
6. **Персистентность:** вкл «Виртуализацию», ребут (или с автозапуском) — настройки на месте.
7. **(Этап 2)** Перенос файла Mac↔Windows, round-trip, миграция старого `config.json` с эмодзи/диакритикой.
8. **(Этап 3)** Типограф на золотом корпусе, двойной прогон (идемпотентность), пустое выделение.

## 7. Работа в Claude Code

- Положить `PLAN.md` и `FORMAT.md` в корень репозитория.
- Первая команда: «прочитай `PLAN.md` и `FORMAT.md` целиком, затем изучи текущие `.swift`-файлы, и начинай с Этапа 1, шаг 1. Иди по шагам, коммить после каждого».
- **Не давать делать всё одним заходом.** Один шаг — один коммит. На границе этапа — собрать, прогнать §6, закоммитить тег этапа.
- Если сессия прервалась — следующая начинается с «прочитай `PLAN.md`, посмотри `git log`, продолжи с последнего незавершённого шага».
- Первый пункт §6 (правый ⌥ на живой машине) проверять на каждом этапе — он самый хрупкий.

## Приложение. Задел под Этап 4 (будущий UI)

Визуальный апгрейд редактора (тёмная тема, типографика, акценты, текстовые подписи невидимых символов) — это **только слой View**, не архитектура. Условие безболезненности: редактор остаётся проекцией `KeyDefinitions` + `Layout`, а подписи клавиш рисуются через `GlyphRenderer` (тот же, что и для автокомментариев). Оба требования выполняются на Этапах 1–2, поэтому отдельной подготовки под Этап 4 не нужно — это будущая перекраска SwiftUI-вью без изменения движка.
