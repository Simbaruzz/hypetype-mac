# hypetype-mac — редизайн редактора раскладки (`DESIGN_PLAN.md`)

Экспериментальная ветка `hypetype-design`. Цель — заменить редактор-сетку 12×4 на
реалистичную мак-клавиатуру (по свежим макетам 2025). Ветка ни на что не влияет:
в `main` ничего не мерджим, пока результат не понравится. Программа в текущем виде
полностью рабочая — это эксперимент без последствий.

---

## 0. Железное правило

**Трогаем ТОЛЬКО слой View. Движок ввода, формат `config.ini`, перехват клавиш,
типограф, ёфикатор, `LayoutStore` — НЕ трогаем.** Новый редактор — это другая
визуализация тех же данных. Это возможно потому, что на рефакторинге (этапы 1–2)
раскладка сведена в единый источник правды `KeyDefinitions`, а редактор сделан
проекцией `KeyDefinitions` + `Layout`. Подписи глифов даёт `GlyphRenderer`.

Из этого правила следует: сломать существующую программу этим редизайном
практически невозможно.

---

## 1. Что делаем в v1

1. **Реалистичная мак-клавиатура** (тёмная тема, фиолетовый акцент для Shift-слоя).
2. **Клавиша «ТИПОГРАФ»** — визуальная афишка фичи R⌥+⌫ (пока некликабельная/
   информативная; хоткей и так работает).
3. **Кнопка (i) → мини-инструкция** — тоггл текстовой подсказки внизу окна
   (сейчас текст висит постоянно; станет по кнопке).
4. **Попап редактирования клавиши** — по клику на активную клавишу: два поля
   (верх = Shift-слой, низ = обычный), подписи аккорда (`⌥+⇧+S`) и имя глифа
   (`shift symbol` / `paragraph`), кнопки «отмена» / «сохранить». Логика уже есть
   в `KeyEditSheet` — переиспользуем, меняем оформление.

## 2. Что НЕ делаем в v1 (отложено в v2)

- **Кастомные подписи клавиш пользователем.** Идея хорошая, но требует хранить
  новые данные → затрагивает `config.ini` (кросс-платформенный, общий с Windows) →
  отдельный разговор с оглядкой на совместимость. Возможный путь на будущее —
  мак-специфичная секция `[macOS]`, чтобы не трогать общий формат. В v1 — только
  авто-имена от `GlyphRenderer`.

---

## 3. Ключевое уточнение по подписям

- **На клавишах подписи-названия НЕ выводятся.** Клавиша показывает только глиф(ы):
  бледная физическая буква (Q, W, E — из `KeyDefinitions.displayLabel`) + настроенный
  символ (обычный снизу, Shift-слой сверху фиолетовым).
- **Человекочитаемое имя глифа** («paragraph», «shift symbol», «No-break space»)
  показывается ТОЛЬКО в попапе редактирования. Источник имён — `GlyphRenderer`
  (при необходимости расширим его словарь дружелюбными формулировками из макета).

---

## 4. Логика сетки (со слов автора, проверено в Figma-автолейауте)

Ряды предсказуемы: квадратные клавиши фиксированного размера + «резиновые» клавиши,
которые растягиваются, добивая ряд до общей ширины. В SwiftUI это ложится один-в-один:
квадрат = фикс `frame(width: 72, height: 72)`; резиновая = `frame(maxWidth: .infinity)`.

- **Базовый квадрат:** 72×72 px.
- **Резиновые ориентир:** «ТИПОГРАФ» и «Tab» ≈108 px; остальные резиновые
  (CapsLock, Enter, Shift, Space) считаются автоматически.

Ряды:
1. **Верхний:** 13 квадратов (Ё-заглушка/`` ` ``, 1…0, -, =) + **ТИПОГРАФ** (резиновый).
2. **QWERTY:** **Tab** (резиновый, = ширине ТИПОГРАФ) + 13 квадратов (Q…`\`).
3. **ASDF:** **CapsLock** (резиновый) + 11 квадратов (A…`'`) + **Enter** (резиновый, = CapsLock).
4. **ZXCV:** **Shift** (резиновый) + 10 квадратов (Z…`/`) + **Shift** (резиновый).
5. **Нижний (декоративный):** FN CTRL OPT CMD — SPACE (широкий) — CMD OPT + стрелки.

Все клавиши, кроме ~48 настраиваемых, — **декоративные** (приглушены, не кликаются):
модификаторы, Tab, Caps, Enter, Shift, Space, стрелки, ТИПОГРАФ.

> Замечание: `Ё` в левом-верхнем углу — наследие виндовой раскладки, в мак-версии
> там физическая клавиша `` ` ``/`§`. Уточнить при верстке.

## 5. Компоненты (предполагаемая структура)

- `KeyboardEditorView2.swift` — новый корневой вью (рядом со старым, не заменяет).
- `KeyCapView.swift` — одна клавиша: физ. буква + глиф(ы), состояние активна/декор.
- `KeyEditPopup` — попап редактирования (переиспользует логику `KeyEditSheet`).
- Модель ряда — данные: массив клавиш `{ kind: mappable(w3cName) | flexible(role) |
  decorative(label) }`. Ширина считается из kind. Это убирает ручной стаггеринг.

Данные: `KeyDefinitions` (физическая метка + keycode + ряды) → уже есть нужные ряды
(`numberRow`, `qwertyRow`, `asdfRow`, `zxcvRow`); `Layout` (что настроено);
`GlyphRenderer` (имена в попапе).

## 6. Открытые вопросы (визуал — уточним по Figma / на глаз с итерациями)

- Точный фиолетовый акцент (hex), радиусы скругления клавиш, размеры шрифтов,
  межклавишные зазоры, цвет фона/клавиш.
- Пропорции окна (клавиатура широкая — окно шире нынешнего 950×530).
- Насколько точно повторять физический мак-стаггеринг vs «узнаваемо, но ровнее».
- Пиксель-специфику возьмём из Figma позже (через Figma MCP), либо подгоним итеративно.

## 7. Порядок работы

1. Статичная клавиатура из `KeyDefinitions` (без интерактива) — увидеть форму.
2. Живые глифы из `Layout` на клавишах (обычный + Shift-слой).
3. Клик по активной клавише → попап редактирования → сохранение в `LayoutStore`
   (тот же путь, что у старого редактора).
4. Кнопка (i) + мини-инструкция.
5. Визуальная доводка по Figma.

Старый `KeyboardEditorView` живёт всё это время нетронутым. Переключение на новый —
только когда автор скажет «нравится». До этого — ветка не мержится.
